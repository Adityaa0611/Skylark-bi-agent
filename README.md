# Skylark BI Agent

A conversational business-intelligence agent that answers founder-level questions
by querying monday.com Deals and Work Orders boards live via the GraphQL API.

## Architecture
- `monday_client.py` — thin GraphQL wrapper over the monday.com API (auth, pagination, error handling)
- `normalize.py` — cleans raw monday.com column values into typed pandas DataFrames; computes data-quality/missingness reports
- `app.py` — Streamlit chat UI; uses Groq's LLM API with tool-calling to interpret questions, call `query_deals` / `get_data_quality_report`, and produce natural-language answers with caveats

## Setup
1. Clone this repo and `cd` into it.
2. `python -m venv venv` then activate it (`venv\Scripts\activate` on Windows, `source venv/bin/activate` on Mac/Linux)
3. `pip install -r requirements.txt`
4. Create a `.env` file (see `.env.example`) with:
   - `MONDAY_API_TOKEN` — your monday.com personal API token (Admin → API)
   - `GROQ_API_KEY` — your Groq Console API key
   - `DEALS_BOARD_ID` — the board ID of your Deals board
   - `WORK_ORDERS_BOARD_ID` — the board ID of your Work Orders board
5. `streamlit run app.py`

## monday.com configuration
Import the provided CSVs as two boards named `Deals` and `Work Orders`, using
Status/Date/Numbers column types as described in the assignment. Column IDs are
auto-generated by monday.com on import — run the test snippet described in this
repo's setup notes to discover them, then update `DEALS_COLUMN_MAP` (and the
equivalent for Work Orders) in `app.py`.

## Known data quality handling
- Missing deal values are treated as unknown, not zero, and excluded from totals.
- Dates are parsed across multiple common formats; unparseable dates become null
  rather than crashing.
- The agent surfaces a data-quality/missingness caveat alongside any answer that
  could be affected by incomplete data.
